# Prepare a service handover

- **Status:** inactive backend slice 3; no handover screen, holder/grant or release action.
- **Audience:** separately reviewed operational preparer; API/UI implementer.
- **Start:** genuine full acceptance of an issued SERVICE_ITEM scope.
- **End:** immutable pending plan, one whole root allocation, initial stage and baseline; no Job.
- **Verified:** 2026-11-11, focused backend/API and two-session race tests; no production use.

## Steps

1. Read the acceptance independently. An observation, PO string or PDF is not accepted business.
2. Ask current readiness for the SERVICE_JOB path. Each missing fact names its owning domain and next action. Goods remain accepted/pending because there is no Order target.
3. Select remote or on-site operational context and the customer's contact; on-site work needs an active customer site. These selections cannot change the agreed scope or commercial terms.
4. Preview handover. Review the exact accepted description, operational instructions/contact/site and the fields withheld from Jobs. Operational measure/quantity and undelivered canonical completion conditions remain null.
5. Prepare with the returned ten-minute token and an Idempotency-Key. Missing facts can remain explicit in a pending plan; selected unavailable references must be resolved. Keep the same key and intent for an uncertain network retry.
6. Read the immutable plan and its historical readiness. Current readiness is separate. Preparation is not release, start, completion, stock commitment or finance clearance.

## Refusals and pending work

Changed readiness/contact/site/context needs re-preview (PREVIEW_TOKEN_STALE). A conflicting
second full plan is refused (SCOPE_ALREADY_CLAIMED); matching retries return the original plan.
A suspended or duty-stripped actor cannot replay. Foreign or hidden records are not-found.

Overall NOT_READY is honest: canonical completion conditions, service-cost certainty,
Inventory/Purchasing applicability and the Job receiver still require delivered source/owner
contracts. Preparation-ready operational selections do not waive these blockers. No one can
release this plan through slice 3. The later receiver/release work is separately authorised.
