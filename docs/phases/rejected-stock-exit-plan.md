# Rejected-stock exit (supplier return and scrap) — implementation plan

- **Status:** **Slices 1 and 2 built (2026-10-08): the shared exit core, then the two documents, permissions and API (no UI)**; slices 3–4 not started. Decision: [ADR 0097](../decisions/0097-supplier-return-and-scrap-of-rejected-stock.md) (accepted 2026-10-08). Workstream: grouped package tracking follow-on ([handoff](package-balance-handoff.md)).
- **Depends on:** QA disposition and held/rejected package evidence ([ADR 0094](../decisions/0094-package-aware-supplier-qa-receipts.md)); the sole movement boundary; the central numbering framework.
- **Goal:** rejected stock — grouped or quantity-only — gets a normal, audited, atomic exit through two separate documents, **Supplier Return** and **Scrap**, over one shared posting path. Nothing financial is settled (no AP/GL).

Every slice passes the [feature-completion checklist](../architecture/feature-completion-checklist.md); the lines below name what is specific here. Slices land in order, each committed with its tests, docs and (where user-facing) browser coverage.

## Facts verified before coding (2026-10-08)

1. **Named-layer outbound without disturbing allocation — confirmed, with a seam.** `IssuePoster` allocates oldest-first over `issuableQuantity`; a single optional input, `from_layer_id`, now makes it consume exactly one named layer (`LayerAllocator::allocateFromLayer`), reachable only through `PostInventoryMovement::issueRejectedPosted`, whose single permitted caller is `PostRejectedStockExit` (ratchet: `RejectedExitHasOneCallerTest`). Ordinary issues are unchanged.
2. **Cost — confirmed.** FIFO/SPECIFIC use the consumed layer's own `base_unit_cost` (a SPECIFIC serial item exits its unit); AVCO goes through the pool's normal outflow at the pool average. Both proven in tests.
3. **Two correctness traps found and fixed in the same slice.** (a) `issuableQuantity` computed "already consumed" as `received − remaining`, so an exit would have silently eaten usable quantity; it now subtracts what has exited. (b) the held-stock arithmetic in the inventory overview and `QueryStockAvailability` (`stock_qty − released`) would have counted exited rejected stock as still held and under-reported availability; both subtract exits. The deferred "move needs evidence" trigger was widened to accept `REJECTED_EXIT`.
4. **Registration — done.** Capabilities `purchasing.supplier-return.create/.post` and `inventory.scrap.create/.post` are registered in the module vocabularies (the Action enforces the two `.post` capabilities now; `.create` belongs to slice 2's drafts). Numbering types and routes wait for slice 2.

## Slice 1 — shared exit core (backend, no HTTP) — BUILT

- **Ledger:** an immutable `rejected_stock_exits` table (company-scoped, composite keys): kind `SUPPLIER_RETURN | SCRAP`, document type and line id, `goods_receipt_line_id`, `stock_move_id`, quantity, the QA decision it relates to, `differs_from_qa` and the **outcome-change reason** (required when it differs), request key + payload hash (unique per company). It is the single source for the cap: `available to exit = Σ rejected dispositions − Σ exited`.
- **Read model:** `RejectedStockBalance` (per receipt line: rejected, exited, available, and the per-kind balance that decides "differs"), used by previews and posting.
- **Posting Action:** `PostRejectedStockExit` — locks location and receipt layer in the stable order, re-reads the cap, posts the outbound move **from the receipt layer** through the movement boundary (`PostInventoryMovement` gains a layer-specific entry; FIFO/SPECIFIC at the layer cost, AVCO through the normal engine), writes the valuation feed row with `source_type SUPPLIER_RETURN` or `SCRAP_WRITE_OFF`, the ledger row, and — for a grouped item — the package evidence, all in one transaction. Idempotent per request key; retry reuses the original moment.
- **Package evidence:** a new `REJECTED_EXIT` kind, issue-shaped and anchored on the move, drawing whole `REJECTED` sealed packages and `REJECTED` loose quantity (never opening or splitting). Migration: kind and link column, draw availability allowed for `REJECTED`, a conservation function (composition = predecessor − draw, single allocation = the receipt layer, `REJECTED` at that layer = decided − exited), and the evidence requirement for the two new `source_type`s of a grouped item. Reuses `PackageIssueComposition` with `$from = 'REJECTED'`. `down()` refuses once exits exist.
- **As built:** migration `2026_10_09_100000` (ledger with shape checks, immutability, commit-time cap/consistency/evidence triggers; `stock_moves` anti-bypass for the two exit `source_type`s; `REJECTED_EXIT` evidence with lineage v8, conservation v5, scope guard v5, evidence requirement v4 and a rejected-conservation check; `rejected_stock_exits` rows judged as of their own id so several exits in one transaction each prove their state; the QA conservation check likewise judges dispositions as of their own id). `RejectedStockBalance` is the cap read model; `PostRejectedStockExit` is the single posting Action (authority, scope, idempotency, differing-outcome reason, whole-package declaration, layer-specific move, ledger, evidence). 47 focused tests in `RejectedStockExitTest` plus the ratchet.
- **Tests (as planned, all passing):** FIFO, AVCO and SPECIFIC cost; grouped (sealed whole, loose, mixed usable/held/rejected untouched) and quantity-only parity; cap and over-exit refusal; differing outcome needs a reason; idempotent retry and changed-payload refusal; rollback of a mixed multi-line post; raw-SQL attacks on the new checks; stale evidence; cross-company; the writer matrix entry.

## Slice 2 — documents, permissions and API — BUILT

- **Documents:** Purchasing `SupplierReturn` (supplier, supplier reference/RMA, carrier note, expected credit amount/currency/reference — informational) and Inventory `Scrap` (disposal method/reference); each with lines, `DRAFT → POSTED | CANCELLED`, central numbering (new document types). Draft moves nothing; edit and cancel only while draft; post calls the shared Action. A return's lines must share one supplier, derived from the receipt line.
- **Capabilities:** `purchasing.supplier-return.create/.post`, `inventory.scrap.create/.post` (dedicated; no inference); registered in the owning vocabularies; **no grant migration by inference** (no equivalent duty exists) — administrators via the re-sync, role recipes in the domain doc.
- **API:** Form Requests with capability guards, Resources, `GET` preview of a receipt line's rejected balance and proposed portion (like the QA portion preview), stable `reason_code`s (`NOTHING_REJECTED_TO_EXIT`, `OUTCOME_CHANGE_REASON_REQUIRED`, plus the existing `NEEDS_DECLARED_PORTION`, `DRAW_NOT_ON_HAND`, `STALE_EVIDENCE`); warehouse scope on the layer's location (404 outside); both document routes added to `RecordScopeCoverageTest`; OpenAPI and client regenerated.
- **As built:** migration `2026_10_09_110000` (`supplier_returns`/`_lines`, `stock_scraps`/`_lines`; one warehouse per document; a database guard freezes a document once it leaves DRAFT and lets posting only link each line to its exit; a deferred check that a POSTED document is numbered and has a matching exit for every line). Purchasing: `CreateSupplierReturn`, `UpdateSupplierReturn`, `CancelSupplierReturn`, `PostSupplierReturn`; Inventory: the same four for `StockScrap`; both post through the shared `PostRejectedExitLines` → `PostRejectedStockExit`, number the document with the central framework (`SRN-`/`SCR-` default templates; `inventory.numbering.manage` registered for the scrap format) and are idempotent (a posted document returns unchanged). Read-only `PreviewRejectedStockExit` returns, per line, the rejected and remaining quantity, the differing part and whether a reason is required, the rejected packages with a proposed whole-package portion, the cost basis (the layer's unit cost only for people with `inventory.valuation.view`) and every blocker with its reason code. Endpoints: `supplier-returns` and `stock-scraps` (index, store, show, update, `preview`, `post`, `cancel`) and `goods-receipt-lines/{line}/rejected-stock`. Reads need the document's create or post capability and follow warehouse scope (404 outside it); writes are guarded in the request and the Action. Reason codes: `DOCUMENT_NOT_DRAFT`, `EMPTY_DOCUMENT`, `DUPLICATE_RECEIPT_LINE`, `MIXED_SUPPLIERS`, `MIXED_WAREHOUSES`, `OUT_OF_SCOPE`, plus those of slice 1. The expected credit (amount, currency, reference) is stored and shown as information only.
- **Tests (40 in `RejectedExitDocumentsApiTest` plus the slice-1 suite, which now shares `BuildsRejectedStockWorld`):** the full return lifecycle (preview, draft, edit, post, idempotent re-post, frozen afterwards; a draft changes no stock, valuation or evidence), a scrap whose outcome differs from QA (refused at post until it says why, draft untouched on failure), cancel, over-exit refusal, per-endpoint capability checks and the separation of the two documents, cross-company by id, a limited-scope person, a quantity-only scrap, and the database freeze and fake-post attacks. `RecordScopeCoverageTest` lists the new routes as scoped.
- **Not done in this slice (closed in slice 3):** `MIXED_SUPPLIERS`/`MIXED_WAREHOUSES` were enforced but untested; slice 3's browser spec now proves both refusals through the API.

## Slice 3 — screens — BUILT

- **Entry points (as built):** *Return to supplier…* and *Scrap…* under each line of the receipt's QA panel, shown only when the person holds the document's create capability and that line still has rejected stock to take out; and *Return rejected stock…* / *Scrap rejected stock…* on a grouped item's package card when a location holds rejected stock. The receipt entry opens the new document with the delivery line already chosen; the item entry opens it empty and the delivery is picked on the document. Nothing is shown when there is nothing to take out.
- **Documents (as built):** each document has its own list (search, warehouse, status, card view on a phone), a form page (create and edit while draft) and a detail page, on the shared `ScreenTemplate` shells (pages, not sheets: the form is a workspace with a preview, so they are not in the `presentation.ts` registry). One shared implementation in `features/rejected-exit/` takes a `kind`; the two documents differ only in header fields and wording. The form picks a posted delivery, lists its lines that still have rejected stock, and per line shows rejected / already taken out / still to take out, the quantity, what is left afterwards, for a grouped item the rejected packages and the whole-package portion (the shared `PackageBreakdown` and `PackageDrawEditor`; a sealed package leaves whole), and — when the quantity differs from the QA decision — a required *why* field. A supplier return's expected credit (amount, currency, reference) sits under *Shipping and expected credit*, labelled *information only*; a scrap's disposal method and reference under *Disposal details*. Saving a draft moves nothing. The draft's detail page re-runs the preview, offers **Edit**, **Cancel draft** and **Post …** (each with a plain consequence in a confirmation), and a posted or cancelled document is shown frozen with no controls (its edit address shows a notice).
- **Permissions and scope:** create and post are separate: someone who may only prepare saves a draft and is told that a person with posting permission will post it. The unit cost per litre is shown only to people holding `inventory.valuation.view`. Warehouse scope is the server's: a limited person's list is empty and a document of another warehouse is "couldn't load". Screens are listed in `screen-access.ts`; the menu entries follow it.
- **Mixed documents:** the form tells a person as soon as it can (lines from two suppliers on a return, or two warehouses) and blocks saving; the server's refusal (`MIXED_SUPPLIERS`, `MIXED_WAREHOUSES`) is proved separately in the browser spec through the API.
- **Browser tests (`rejected-exit.spec.ts`, `rejected-exit-mobile.spec.ts`):** grouped return of a rejected can (receipt entry, package preview, expected credit needs a currency, post, frozen, rejected stock gone); grouped scrap from the item page (delivery picked on the document, posted, edit address frozen, delivery no longer offers the exit); QA-decided scrap returned instead (reason required, then frozen with the reason); mixed supplier and mixed warehouse refused on screen and by the server (422 with the reason code); a person who may only prepare; a person limited to their own units; light and dark accessibility and contrast scans of form, draft and list; a 390 px phone run (form, draft, confirmation, list). Fixtures: `rejectedDelivery()` and an extended `createQaOrder()` in `package-stock-support.ts`.
- **Known limitations:** the item entry does not pre-select a delivery. A rejected-stock list across deliveries is still out of scope.

## Slice 4 — demo, rollout and close-out — BUILT

- **Demo (as built):** `RejectedStockExitDemoSeeder`, create-once through the real Actions. A grouped emulsion delivery (3 cans + 4 L loose, 19 L) decided by QA: one can passed, one can rejected for return, one can + 4 L loose rejected for scrap; one **Supplier Return** posted (the can, with an expected credit shown as information only), one **Scrap** posted (a can and 2 L loose) leaving **2 L loose rejected awaiting scrap**; and a quantity-only delivery with 4 L rejected and a **draft** Supplier Return waiting to be posted. Three personas (`demo-exit-preparer`, `demo-exit-controller`, `demo-exit-clerk` — the last limited to their own units), created through the same role and member Actions an administrator uses. `RejectedStockExitDemoSeederTest` proves the balances, numbering, personas and that a rerun adds nothing; the browser specs sign in as these personas, so no Docker-only setup remains.
- **Also fixed while closing out:** the receipt detail screen resolved line items, units and locations from the first 100 rows of a list, so the reversal panel lost the item and unit past 100 items; lines now fetch what they name by id (regression test with more than 100 items sorting ahead).
- **Browser:** one more scenario covers rejected loose litres leaving in part (1 L of 2 L loose scrapped; a can and 1 L stay rejected).
- **Release notes (no new migration in slices 3–4):** migrations of slices 1–2 in order — `2026_10_09_100000_add_rejected_stock_exits`, `2026_10_09_110000_create_supplier_returns_and_stock_scraps`; then `permission:register`; then, for each administrator who should hold the four capabilities (`purchasing.supplier-return.create/.post`, `inventory.scrap.create/.post`, plus `inventory.numbering.manage` for the number formats), `erp:sync-admin-permissions <email>`. Nothing is granted to existing roles by inference. Document numbers default to `SRN-` and `SCR-`; formats are edited under document numbering. Existing rejected stock simply becomes returnable or scrappable; no data is changed by the release. Frontend: new menu entries *Supplier Returns* (Purchasing) and *Scrap* (Stock Operations), shown only to people holding a capability of that document.
- **Docs:** domain doc (screens, role recipes), grouped journey, UI building-blocks catalogue, this plan, the handoff and STATUS.

## Out of scope (deliberate)

AP credit note, supplier balance and GL journals (Phase 6); return reversal (goods coming back); approval thresholds; opening or splitting rejected packages; a standalone rejected-stock list screen (later, with the other menu screens).
